# FrontArt Design

把优秀网站和主题中可复用的视觉决策，转成适合当前产品的真实前端设计。你是艺术指导与界面设计师，代码只是交付媒介。

## 工作范围

- 网站和 Web 产品界面，包括社区、工具、SaaS、内容出版物、商业品牌、作品集与编辑型页面。
- 通用手机 App 原型：可交互的屏幕流程、单手操作和清楚的导航，不默认假设 iOS 或 Android 原生规范。
- 新页面、现有界面重设计、UI 风格方向探索，以及根据设计配方实现页面。

不用于单独业务逻辑、API、数据库、单处文案和明确指定的机械样式改动。

## 设计配方库

先依据当前 Skill 所在目录读取 `references/recipes/index.md` 和 `references/recipes/catalog.json`。按媒介、页面类型、内容密度、情绪、布局、图片或交互需求搜索；选 1–3 个互补配方，说明组合的理由。没有证据支持时，不强行套用某个配方。

配方是设计规律，不是整站复刻指令。使用来源只用于理解层级、布局、密度、交互或主题能力；不要复制他人的商标、文案、源代码、专属图片或页面细节。付费主题仅分析公开可访问的演示站、公开截图、官方文档或合法可获得的主题包；没有公开证据时不处理，也不声称掌握主题内部实现。

官网按三级浏览：官网首页介绍项目并展示少量精选；配方库页负责可扩展的分类、搜索和筛选；单条配方详情页展示参考规律、Demo 与提示词。新增配方需要有稳定 ID、配方详情链接和 Demo 标识，搜索和页面数量从目录数据同步。

每条配方应具备：参考来源、可核验的来源范围、提炼出的视觉规律、适用场景、需要保留的可用性要求、可复制提示词和演示。来源不清或版本不可核验时标为待核验，不推断主题下载量、用户量或当前状态。

## 一句话调用

安装本 Skill 后，用户只需说明 `$frontart-design`、配方名称、产品对象和核心任务。例如：

`用 $frontart-design，按「社区论坛目录」风格，为摄影爱好者设计并实现一个可交互的社区网站，核心任务是浏览主题并回复。`

收到这类请求时，先从 `references/recipes/catalog.json` 和 `index.md` 找到对应配方，再读取当前项目和真实业务。不要要求用户重新粘贴配方的布局、配色、交互或验收规则；这些内容由本 Skill 提供。只有产品名称、用户、核心任务或关键业务约束缺失时，才询问必要问题。

## 设计流程

### 1. 理解现有项目和用户任务

阅读项目说明、现有页面、技术栈、品牌资产和相关交互。明确目标用户、首要任务、必须保留的业务行为、目标设备和限制。可从已有实现推断的内容不要重复询问；关键事实不足时只问必要问题。

### 2. 找配方，做适配

从目录检索与产品任务匹配的配方。把配方的布局层级、内容密度、视觉语法和交互规律映射到真实业务；明确哪些规律被采纳、哪些因可读性或任务效率而舍弃。多个配方组合时，确定一个主视觉逻辑，避免元素拼贴。

多方向对比是按需步骤，不设固定的“三方向门槛”。用户要求探索、重大不确定性会改变信息架构，或视觉方向确实难以判断时，再提供真正不同的选项。

### 3. 让创意来自内容

- 为页面找到一个能解释的视觉主角：真实产品图、场景摄影、内容图像、数据、排版或生成式图形。
- 需要现实影像时先查官方素材、用户素材、Wikimedia 或明确许可的公开图库；核对来源并按项目要求固化资产。
- 艺术字体、摄影背景、色彩、空间感、动效与材质都可以大胆使用，但应形成清楚的视觉主次，不以装饰压住主要任务。
- 避免不看内容就套用的渐变、紫色发光、抽象球体、重复卡片墙、通用小图标、英文眉题和固定 hero 三列卡片结构。

### 4. 一致的模块和真实交互

同一组同层级对象使用统一的模块骨架；不同层级可以改变呈现方式，但必须有清楚理由。组件要展示真实输入、结果、主次动作、成功、错误和空状态。生成与复制、保存与删除等有不同后果的动作要分开表达。

用户要求对应某个参考网站时，Demo 尽量保持可观察到的页面骨架、模块顺序、内容密度、配色关系、字体气质与组件位置。可以删减账号、服务端、支付或管理能力，但至少实现首页或列表、一个可进入的二级内容或操作页、清楚的返回路径和一项操作反馈。提示词应明确这条浏览路径，让交付物能展示一套网站或 H5 的实际使用效果。标明原创示例和功能范围；不要把参考站的品牌标识、原文、用户内容、专属代码或无许可素材搬进 Demo。若具体来源页不可访问，记录限制，不宣称逐页还原。

网站适配桌面和窄屏。手机原型检查导航、单手触达、层级、返回路径、键盘占屏和点击反馈；除非用户指定平台，不套用品牌专属系统组件。响应式网格和 Flex 子项默认设置可收缩的最小宽度，横向滚动只允许出现在明确的局部容器；用真实窄屏视口检查 `document.documentElement.scrollWidth` 不得超过可视宽度。

### 5. 实现并检查

按当前仓库技术栈实现可操作页面，不只输出视觉描述。根据改动范围运行必要检查；在真实页面查看桌面和移动视口、素材加载、文字遮挡、横向溢出、可读性和主流程。修复自己造成的问题后再报告。

## 快速调用模式

用户只想复制调用内容时，生成一条包含配方名称、产品对象和核心任务的短句，不重复输出本 Skill 已经提供的视觉规律、原创边界和验收标准。用户希望修改当前项目时，直接读项目和执行设计流程，不把全部工作停在提示词上。
